# 题目分配与超时机制设计

## 1. 需求背景

当多用户同时参与测试时，需要合理的题目分配策略和超时释放机制。

场景：2道题，每题需3人，4个用户同时做题

## 2. 设计方案

### 2.1 题目分配逻辑（轮询）

- 优先分配**回答人数最少**的题目
- 当多道题回答人数相同时，按**轮询**方式分配
- 用户每次只能领取一道题

### 2.2 锁定机制

- 用户领取题目后，该题被锁定（`locked_by`）
- 锁定期间其他用户仍可领取同一道题（允许多人同时做）
- 提交答案后更新回答人数

**注意**：实际实现中简化了锁定逻辑，多个用户可以同时领取同一道题，系统通过检查用户是否已回答过该题来避免重复提交。

### 2.3 超时释放

- 用户领取题目后开始计时
- 超时时间由Agent自定义，默认60秒
- 超时后题目自动释放，其他用户可领取
- 超时用户无法获得积分

### 2.4 积分规则

| 情况 | 积分 |
|------|------|
| 正常提交（未超时+未满员） | +10 |
| 超时未提交 | 0 |
| 题目已满员被拒绝 | 0 |

## 3. 数据模型变更

### TestQuestion 新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| locked_by | Integer (nullable) | 当前锁定用户ID |
| lock_expires_at | DateTime (nullable) | 锁定过期时间 |
| timeout_seconds | Integer | 超时时间，默认60 |

### QuestionCreate 新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| timeout_seconds | Integer (optional) | 超时时间，默认60 |

## 4. API变更

### 4.1 创建任务（Agent）

```json
{
  "task_type": "ui评估",
  "content": "测试两个界面",
  "questions": [
    {
      "content": "A和B哪个更好看？",
      "options": ["A", "B"],
      "required_answers": 3,
      "timeout_seconds": 60
    }
  ]
}
```

### 4.2 获取下一道题（用户）

响应中增加锁定信息：

```json
{
  "question_id": 1,
  "content": "A和B哪个更好看？",
  "options": ["A", "B"],
  "lock_expires_at": "2026-04-01T12:00:00"
}
```

## 5. 实现要点

1. **轮询分配**：使用题目ID和用户访问顺序实现轮询
2. **超时检查**：每次领取题目时检查是否有超时的锁定
3. **自动释放**：清理过期锁定，释放题目给其他用户
4. **积分控制**：只有在有效提交时才发放积分
